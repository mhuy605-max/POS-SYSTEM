# UI + Motion Polish V2 Implementation Plan

**Goal:** Modernize the Đakao In Bill presentation layer with the approved warm-utility art direction while preserving every Stage 1–6 domain, persistence, printing, revenue, and backup behavior.

**Base:** `feature/full-pos` at `9204482642d10c17ac60213e15d8b605408a5b18`

**Branch:** `polish/ui-v2`

## Architecture

The existing Riverpod controllers, repositories, Drift schema, router destinations, and native printer boundary remain unchanged. Presentation changes are organized in three layers:

1. `lib/app/theme.dart` owns semantic colors and the global Material theme.
2. `lib/app/design_system.dart` owns spacing, radii, component sizes, motion tokens, semantic status presentation, and reusable empty/loading/error/press feedback widgets.
3. Feature screens compose those tokens and primitives while retaining their current state providers and callbacks.

Flutter built-ins provide all motion. State updates happen immediately; short implicit transitions only explain the resulting visual change. Reduced-motion requests collapse those durations.
